# 原型生成（prototype）

## 目的

在系统需求分析阶段，做出系统的界面原型，展示给用户。

## 执行者

`product-manager`

## 输入

- `docs/requirements/overview.md`、`biz-$MOD.md`、`spec-$MOD.md`

## 输出

- `pages/prototype/`（原型文件）

## 交付形态（按复杂度选择）

1. **轻量**：单页 HTML（内联 CSS，无构建），可静态打开预览。
2. **说明式**：Mermaid 页面流转图 + 每个页面的元素清单（表格式线框描述）。
3. **可交互**：多页 HTML + 简单 JS（仅当需求要求交互确认时）。

> 默认优先轻量单页 HTML，避免为原型引入构建链。

## 要求

- 覆盖需求中的主要界面（登录、列表、表单、详情等）。
- 每个界面标注服务的功能编号 `fr-$MOD-xxx`。
- 明确**交互流程**（页面流转，Mermaid）。
- 只做原型，不实现真实逻辑（不接后端）。

## 检查清单

- [ ] 覆盖主要界面
- [ ] 界面标注功能编号
- [ ] 页面流转图齐备
- [ ] 已展示给用户确认

## 触发与边界

**该用**：需求阶段让用户"看见"界面，尽早对齐预期。

**不该用**：
- 真实前端实现（接口调用、状态管理）→ 属 ui-developer 编码任务
- 只做静态展示不需要交互 → 说明式线框 + Mermaid 亦可

## 常见错误

- 原型接后端/写真实逻辑（原型只表达"长什么样、怎么走"）。
- 界面不标功能编号，无法与需求对齐。
- 为原型引入构建链（默认优先零构建单页 HTML）。
