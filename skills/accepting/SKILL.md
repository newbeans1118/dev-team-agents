# 项目验收（accepting）

## 目的

在系统交付前，对项目进行总体评估，确认功能与质量是否达到预期目标。

## 执行者

`project-reviewer`（评审人另含**用户**）

## 输入

- `docs/PROJ_$PROJECT_NAME.md`
- `docs/requirements/`
- `design/`
- `review/`（各阶段评审报告）
- `test/report/`
- `release/`

## 输出

- 立项评审：`review/project/RV-PROJ-KICKOFF.md`
- 项目验收评审：`review/project/RV-PROJ-ACCEPT.md`

## 立项评审要点

- 可行性（技术、资源、周期）
- 功能完备性（覆盖核心诉求）
- 材料完整性
- 技术选择合理性与技术风险

## 验收评审要点

1. 目标达成度：biz-xxx / fr-xxx 的实现与验收情况回溯
2. 评审闭环：需求/设计/代码/测试各阶段结论是否通过
3. 缺陷清零：P0/P1 是否清零
4. 非功能达成：性能/安全指标是否达标
5. 发布物：是否符合生产版条件（四方联合确认）
6. 遗留风险与未交付项

## 结论

给出**通过 / 不通过**，并列出阻塞项与后续动作。评审结论须标注是否已获用户确认（用户是共同评审人）。

## 检查清单

- [ ] 目标达成度逐条回溯
- [ ] 各阶段评审结论已核对
- [ ] P0/P1 清零
- [ ] 非功能指标核对
- [ ] 明确通过/不通过结论

## 触发与边界

**该用**：立项评审（项目开头）与项目验收（交付前）这两个"总体评估"门禁。

**不该用**：单阶段评审（需求/设计/代码各有专门技能）。

## 常见错误

- 验收不看各阶段评审是否真正闭环，只看测试报告。
- P0/P1 未清零仍给"通过"。
- 不核对发布物是否符合生产版条件（四方联合确认）。
- 跳回立项目标核对，导致"做完了但没做对"。
