# 通用设计（general-design）

## 目的

设计关键流程的算法与数据结构、组件的对内/外接口，以及日志设计；完成软件模块与功能设计。

## 执行者

`architect`

## 输入

- `docs/requirements/spec-$MOD.md`
- `design/ARCH.md`、`design/DATABASE.md`

## 输出

| 文件 | 内容 |
|------|------|
| `design/FUNC.md` | 软件模块及功能设计 |
| `design/DATASTRUCT-ALGORITHM.md` | 关键流程的数据结构与算法设计 |
| `design/INTERFACE.md` | 内部接口、对外接口设计 |
| `design/LOGGER.md` | 日志设计 |

## 内容要求

### FUNC.md
- 以模块为单位组织；每个功能设计条目标注对应 `fr-$MOD-xxx`。
- 条目含：功能说明、处理流程（Mermaid）、依赖、异常路径。

### DATASTRUCT-ALGORITHM.md
- 针对**重要、复杂**功能：数据结构选型 + 算法描述 + 复杂度分析。
- 给出伪代码或关键片段，说明边界条件。

### INTERFACE.md
- **内部接口**：模块间接口（函数/协议），含签名、参数、返回、异常。
- **对外接口**：REST/RPC/消息等，含路径、方法、请求/响应 schema、错误码。
- 每个接口标注服务的功能编号。

### LOGGER.md
- 日志目录、日志文件构成（按模块/级别切分）
- 日志格式（字段、时间格式、级别枚举）
- 记录内容（哪些事件记、哪些不记）、脱敏规则

## 质量要求

- 所有设计可追溯到功能编号；无对应功能的接口/结构不写。
- 接口契约完整，异常路径必须定义。
- 日志不得记录敏感信息明文。

## 检查清单

- [ ] FUNC.md 每条设计可追溯
- [ ] 复杂流程有数据结构与算法设计
- [ ] 内外接口契约完整
- [ ] 日志设计含目录/文件/格式/内容

## 触发与边界

**该用**：架构定了之后做模块级详细设计。

**不该用**：
- 定架构与选型 → 用 `architecting`
- 设计数据库 → 用 `data-modelling`
- 评审设计 → 用 `design-review`

## 常见错误

- 无对应功能编号的接口/结构也写（冗余设计）。
- 接口只写正常路径，不定义异常与错误码。
- 日志记录敏感信息明文（违规）。
- 算法设计不给复杂度与边界条件。
