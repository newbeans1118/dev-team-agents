# 数据模型评审（datamodel-review）

## 目的

专项评审数据库设计，是设计评审的深化子集（聚焦数据层）。

## 执行者

`design-reviewer`

## 输入

- `docs/requirements/dict.md`
- `design/DATABASE.md`
- `docs/requirements/spec-nonfunc.md`

## 输出

- `review/design/RV-DM-xxx.md`

## 评审角度

| 编号 | 检查点 |
|------|--------|
| 1 | 实体关系是否准确反映业务实体与状态机 |
| 2 | 字段类型/长度/精度是否合理（金额、时间、枚举） |
| 3 | 主键/唯一约束/外键是否恰当 |
| 4 | 索引是否覆盖高频查询、是否冗余、是否影响写性能 |
| 5 | DDL 是否可执行、是否与数据字典一致 |
| 6 | 范式与反范式取舍是否合理 |
| 7 | 敏感字段加密/脱敏是否落实 |
| 8 | 容量与扩展（分表分库、归档）是否有预案 |

## 报告格式

问题编号 `RV-DM-xxx-NN`、级别、位置（表/字段/索引 + DDL 行）、问题描述、修改建议、状态。附总体结论。

## 闭环

报告 → 架构师修改 → 回复 → 评审员验证 → 关闭。

## 检查清单

- [ ] 8 个检查点逐项覆盖
- [ ] DDL 与字典一致性核对
- [ ] 索引逐条有依据
- [ ] 结论明确、问题闭环

## 触发与边界

**该用**：数据库设计需要专项深化评审时（设计评审的数据层子集）。

**不该用**：整体设计评审 → 用 `design-review`；变更走 `requirement-review`/`code-review`。

## 常见错误

- 只看表结构不验 DDL 可执行性。
- 不核对 `dict.md`，漏检字段不一致。
- 索引只数个数不问"服务哪条查询"。
