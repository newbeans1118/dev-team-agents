# 数据库设计（data-modelling）

## 目的

设计数据库：数据模型、索引、DDL，产出可执行、与数据字典一致的数据库设计。

## 执行者

`architect`

## 输入

- `docs/requirements/dict.md`（数据字典）
- `docs/requirements/spec-$MOD.md`
- `docs/requirements/spec-nonfunc.md`（性能指标影响索引设计）

## 输出

- `design/DATABASE.md`

## 内容要求

1. **数据模型**：实体、属性、关系、主键/外键。
2. **E-R 图**：Mermaid `erDiagram`。
3. **数据字典映射**：概念模型实体 ↔ 物理表。
4. **索引设计**：针对查询模式设计索引，说明每张表索引及其支撑的查询；避免冗余索引。
5. **DDL**：完整可执行的建表语句（含约束、注释）。
6. **数据生命周期**：归档、清理策略（如需求涉及）。
7. **安全**：敏感字段脱敏/加密策略（与安全需求一致）。

## 质量要求

- DDL 与数据字典字段一一对应，不凭空加字段。
- 每个索引必须说明它服务于哪些查询/功能编号。
- 范式适用为度：不过度规范化也不冗余失控。
- 图形一律 Mermaid。

## 检查清单

- [ ] ER 图齐备
- [ ] DDL 可执行
- [ ] 索引有依据
- [ ] 字段与数据字典一致
- [ ] 敏感字段策略明确

## 触发与边界

**该用**：需要落地数据存储结构时。

**不该用**：
- 定义业务实体语义 → 用 `requirement`（数据字典）
- 设计整体架构 → 用 `architecting`
- 专项评审数据模型 → 用 `datamodel-review`

## 常见错误

- DDL 字段与 `dict.md` 不一致（凭空加字段）。
- 索引无查询依据，或堆冗余索引影响写性能。
- 金额/时间/枚举的字段类型与精度选错。
- 敏感字段未落实加密/脱敏。
